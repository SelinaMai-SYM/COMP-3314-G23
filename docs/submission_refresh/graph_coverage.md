# Complete intended graph coverage

`experiments/submission_refresh/graph_coverage.py::build_graph_coverage(artifact_root, output)` builds `graph_execution_coverage.csv` and `graph_coverage_manifest.json` from metadata only. It enumerates the complete frozen `configs/submission_refresh/graph_queue.json`: 362 intended tasks, comprising 2 G1 casebooks, 48 G2 points and 312 G3 points. The helper rejects missing/duplicate intended tasks or configuration/run-ID inconsistencies before replacing output. It does not open matrix objects, fit models, evaluate labels, choose scores or alter the intended grid.

One row represents one intended task. Controller status is separate from saved scientific output. A failed or timed-out controller can retain a complete point; a completed controller can still lack its required output. Saved point completeness requires the matching configuration identity and all 50 unique valid rounding records, independently of its certificate. Certificate fields report the recorded solver claim, relative gap and edge/node capacity residuals; the helper does not recompute a dual bound or verify matrix objects. Multiple input versions remain explicit and are not collapsed to the best result. Identical recorded mathematical problem IDs and gamma-zero graph-arm aliases are retained without counting them as independent reruns.

G1 has its own casebook criterion. Its complete sample table, frozen full-benchmark sample/class counts, 50 paired-seed and per-class diagnostics, and object references must be present. A G2/G3 point file cannot satisfy a G1 casebook. The coverage records say explicitly that object/archive availability is checked separately.

Unlaunched tasks are `NOT_RUN`, or `PENDING` when a saved scheduler queue lists them. A ledger reservation marks a task `RUNNING`; launched failures retain their recorded state. `NOT_RUN_BUDGET` is used only when no shared jobs are active and the task's frozen reservation cannot fit the remaining non-finalization allowance. This budget classification uses the shared ledger, not performance. Raw controller evidence, aliases, scheduler flags, metadata paths and hashes remain available beside these summary states, including stale queue evidence rather than silently replacing it.

The manifest records the exact intended queue and frozen membership inventory hashes, every metadata input hash, status counts and the generated CSV hash. Final aggregation generates this view and the scalar evidence release hash-locks/copies both files for a no-data checkout. Prepared fixtures cover unlaunched tasks, controller failure with saved complete points, G1 separation, problem aliases, incomplete seed sets, uncertifiable residual metadata, pending/budget states and failure before replacement. Those prepared checks do not by themselves establish that a graph experiment ran.
