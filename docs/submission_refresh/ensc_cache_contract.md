# EnSC construction and input cache contract

The shared graph/SSC scientific fingerprint and fitting formulas remain unchanged. EnSC adds a separate construction identity over the actual local input, coefficient, native-spectral, wider/random control and movement helpers, their calling adapter and required dataset/grid constants. Selected external input-loading and rounding helper ASTs are included. Relevant module import bindings and global rebindings are recorded too, so unchanged helper text cannot hide a different imported implementation. Comments and docstrings are removed; unrelated scalar aggregation, report generation and display functions are excluded. Full source bytes and commits remain recorded separately.

The EnSC F0 cache key includes its input-adapter behavior, actual X/y object identities, K, Y0 preparation and the shared graph source/environment identity. A matching cached representation must carry that same input-adapter identity. Coefficient parameters bind construction behavior/source as well as the input, backend, environment and fixed numerical parameters. G4 resume contexts bind the construction identity for every control and the input-adapter identity; native-spectral results cannot silently survive a changed native helper. Existing contexts without these fields fail comparison rather than being promoted as current.

For an existing G3 input, EnSC requires matching exact X/y objects, K, Y0 and graph source, then verifies the recorded EnSC input-adapter and external loader source. Identical recorded bytes are sufficient. If only editorial/unrelated code changed, a recoverable JSON source archive must match its recorded hashes and show the same fitting AST. Missing, corrupt or incompatible source evidence fails before replacing the gated F0. Compatible reuse returns the exact saved G3 F0 objects and leaves its representation file untouched; compatibility provenance is added only to the EnSC return metadata. No source version is inferred from a hash without recoverable evidence.

The scalar derivation explicitly reads current `G4-resume-context-v2` records and requires their input-adapter and construction identities. The input-adapter fingerprint and context schema are part of the common per-benchmark provenance, so they cannot be mixed across rows or job folders. A construction fingerprint is shared across all current controls. The elastic-net backend hash is required and compared only for the EnSC graph families, including their native spectral controls; W0, Wa, wider-kNN and randomized controls correctly have no backend hash. A missing backend hash on those controls is not a conflicting construction source.

The pure historical scalar reader also supports an internally consistent `G4-resume-context-v1` track with its original exact input/source/environment bindings. It records that schema and its absent input-adapter field explicitly and rejects mixing it with v2. This compatibility does not make a v1 fit checkpoint reusable as a current v2 checkpoint: the fitting cache still requires equality with the full current context. Neither reader infers a missing v2 binding from another row.

This is a conservative cache/provenance change before G4 execution, with no new loss, grid, solver or fitting formula. Prepared fixtures exercise changed input/native behavior, unchanged editorial behavior, archived-source verification, exact G3 F0 reuse without a builder call, and own-input cache invalidation using dummy builders. These checks have not been run by this editing task; the shared validation queue records their actual outcomes.
