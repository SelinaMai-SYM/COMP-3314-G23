# Graph and EnSC scheduler resume checks

An existing `task_status/<run_id>.json` no longer bypasses graph or EnSC provenance checks. After either callback returns, the scheduler attaches `scheduler_resume_identity` to its controller record. This locks the exact task, including CPU/fit limits and profile flags; scientific behavior fingerprint and environment; fixed input record path and SHA-256; and, for EnSC, the gate/backend authorization hashes and pinned source revision. A failure before authorization or input creation retains an explicitly unavailable identity.

Before skipping a saved task, the scheduler requires a terminal status compatible with its profile/formal track and an unchanged locked identity. It compares the current full-benchmark loader output with the saved X/y using the existing matrix fingerprint, and verifies every fixed input CAS object. It checks Y0, the declared dataset/K, and the source/environment of the saved representation. It never calls graph, embedding, coefficient, solver or rounding builders and never replaces saved arrays.

EnSC uses its existing authorization checker before any fixed-input path, object-store or benchmark-data access. The current immutable promotion record and backend verification must match the original authorization exactly. G3-input reuse also passes the existing source-byte/archived-fitting-AST input-adapter check; a separate EnSC input must retain its input-adapter fingerprint. The current construction fingerprint includes the native spectral and control-building helpers, so changed helper behavior cannot silently reuse a prior controller result.

Within one scheduler invocation, current source/environment and current loaded data fingerprints are reused per dataset. The data root and source must remain frozen during that invocation, as during fitting. Input metadata is rehashed, and object hash checks are repeated when a file's size, modification time or inode changes. Resume metadata CPU, including short Git child checks, is returned separately for final resource accounting. No additional worker pool or scientific search is created.

Missing legacy locks, changed task/caps, altered gate/backend evidence, changed source/environment, changed data or corrupt input artifacts fail closed with a request to preserve the original record and use a new run ID. They do not trigger a fresh fit under the old identity. Prepared fixture checks cover unchanged scheduler skips, per-controller reuse, source/environment/data/cap changes, locked metadata, EnSC helper changes, authorization-first ordering, profile identity capture and unavailable pre-authorization failures. Their actual validation status belongs to the shared validation job record.
